# 检测面评估（PAC / 5E / VAC）· 2026-11-13 架构 v2

## 0. 结论先说

**无法保证在 PAC / 5E 下不被检测。** 这两家是「内核驱动 + 表完整性校验 + 行为风控 + 人工录像审查」的组合，
规则不公开、且持续升级；任何声称"保证不封"的说法都不成立。

能给出的是**逐项对照的暴露面**和**已经压掉的特征**。当前链路：

| 平台 | 风险 | 依据 |
|---|---|---|
| VAC（官匹） | 低 | 不注入、不写游戏内存、无指向 cs2.exe 的句柄、无游戏内模块 |
| PAC（完美） | **高** | 内核 unbacked code + kdmapper 表清理痕迹 + 用户态进程/窗口可枚举 |
| 5E | **高** | 同上，另有扫盘与驱动特征库 |

风险"高"指的是**存在明确、可稳定复现的检测点**，不是"一定会被封"——是否处置取决于对方规则与人工审查。

## 1. 逐项对照

| 检测项 | PAC | 5E | VAC | 本项目现状 | 判定 |
|---|---|---|---|---|---|
| 游戏进程内模块/线程扫描 | ✓ | ✓ | ✓ | 不注入、不建远程线程 | 无 |
| 游戏内存写入 / .text 完整性 | ✓ | ✓ | ✓ | 纯读，零写入 | 无 |
| 句柄枚举（PROCESS_VM_READ 指向 cs2） | ✓ | ✓ | 部分 | `PsLookupProcessByProcessId` + `MmCopyVirtualMemory`，不建句柄 | 无 |
| 驱动对象 / 设备对象枚举 | ✓ | ✓ | ✗ | 不创建 | 无 |
| 服务 / 注册表枚举 | ✓ | ✓ | ✗ | 不注册 | 无 |
| `PsLoadedModuleList` 模块列表 | ✓ | ✓ | 部分 | 手工映射，不在列表 | 无 |
| **非模块可执行内核内存（unbacked code）** | ✓ | ✓ | ✗ | 驱动镜像在独立页，RWX 已按段拆分但仍是 unbacked | **命中** |
| **PiDDBCacheTable / MmUnloadedDrivers / 内核哈希桶** | ✓ | ✓ | ✗ | kdmapper 会清理这三处，清理动作本身留痕 | **命中** |
| **CodeIntegrity 事件日志（驱动加载）** | 可能 | 可能 | ✗ | iqvw64e.sys 通过 NtLoadDriver 加载，事件可查 | **命中** |
| 进程枚举（未知可执行文件） | ✓ | ✓ | ✗ | `CS2ESP.exe` 常驻 | **命中** |
| 窗口枚举（overlay 特征） | ✓ | ✓ | ✗ | 类名每次随机、标题空、`TOOLWINDOW`+`NOACTIVATE`；仍是 topmost 分层窗口 | 可发现 |
| 对象目录（命名 section） | 部分 | 部分 | ✗ | GUID 名，仅在游戏运行时存在 | 可发现 |
| ETW / 内核回调观察读内存 | 部分 | 部分 | ✗ | 60 Hz 的 `MmCopyVirtualMemory` | 可观察 |
| 输入注入 / 低级钩子 | ✓ | ✓ | ✓ | 不做 | 无 |
| DMA 硬件检测 | ✓ | ✓ | ✗ | 不用 DMA | 无 |
| 录像 / 人工审查 | ✓ | ✓ | 部分 | 细线、低饱和、无闪光特效 | 取决于观感 |

## 2. 本轮（2026-11-13 晚）做了什么

| 改动 | 效果 |
|---|---|
| 采样 120 Hz → **60 Hz** | 跨进程读次数减半（每秒约 260 次），降低 CPU 时间与页访问密度 |
| overlay 窗口类名**每次启动随机**、标题置空、加 `WS_EX_NOACTIVATE` | 去掉固定的 `WindowClass`/`Window` 特征；不抢焦点 |
| **帧正文 XOR**（key 由目标 pid 派生），仅头部 16 B 明文 | 直接 dump section 只能读到 magic/seq，玩家名/坐标是密文（实测 `Larry`/`DayZz` 不可见） |
| 骨骼索引修正、开镜矩阵缓存 | 功能修正，同时减少"异常画面"带来的观感暴露 |
| 共享内存通道代号 SALT=5 | 多实例隔离 |

**没有改变**：内核层的三项命中（unbacked code、表清理痕迹、CI 日志）。这三项由"手工映射"这个方式本身决定，
不是代码写法能绕过的。

## 3. 要把内核层降下来，只有三条路

| 路线 | 代价 | 效果 |
|---|---|---|
| 合法签名驱动（EV 证书 + 微软 attestation 签名） | 个人基本拿不到；企业主体可申请 | 消除 unbacked + 表清理痕迹 |
| 代码洞植入（把逻辑写进已签名驱动的 padding，`cs2_cave.c` 有探针） | 需要找可用洞、有完整性校验风险、蓝屏风险 | 消除 unbacked，但仍在"被改写的签名模块"里，可被哈希比对 |
| 不碰主机（DMA 卡从 PCIe 读物理内存） | 需要硬件（数百到数千元），且 PAC/5E 已有 DMA 检测 | 主机侧零痕迹，但对方明确在查 DMA |

> 现工程里 `core/driver/src/cs2_cave.c` 是 code cave 的**只读探针**（`-Cave` 编译开关），
> 没有默认启用——因为它要写别的驱动的 padding，失败就是 0x139/0x1E 蓝屏。

## 4. 用户态还能做的（需要用户配合，不在 exe 内）

1. **改 exe 文件名**：`CS2ESP.exe` 这个名字本身就是特征，改名为任意系统风格的名字（如 `InputHost.exe`）。
2. **不要放在桌面/下载目录**：进程路径也会被记录，放 `C:\ProgramData\...` 之类。
3. **不要同时开 OBS/录屏**：overlay 会被录进去，人工审查直接定位。
4. **观感收敛**：菜单里把方框改细、颜色调低饱和、关掉骨骼只留方框；ESP 的视觉特征是人工封禁最常见的依据。
5. **不要在平台排位里长时间开着**：行为数据（命中率、预瞄）与 ESP 的相关性会被风控建模。
