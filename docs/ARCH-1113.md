# 外部覆盖层 · 架构 v2（共享内存通道）

2026-11-13。本版把帧通道从"隐藏文件"改成**内核建立的共享内存 section**，
显示端只做只读映射；文件落盘降级为可选镜像（默认关闭）。

## 1. 目标与硬约束

| # | 约束 | 落地方式 |
|---|---|---|
| 1 | 显示端全程不附加、不读取 cs2.exe | 唯一数据源是共享内存；进程列表只用于取 pid |
| 2 | 不注入、不写游戏内存 | 驱动只做 `MmCopyVirtualMemory` 读 |
| 3 | 低延迟 | 驱动 120 Hz 采样，每帧直接写映射视图；显示端 memcpy 一次 |
| 4 | 崩溃安全 | 帧长固定、seqlock、每段自带 magic/FNV、读端校验 |
| 5 | 可维护 | 帧布局只追加不改旧偏移；偏移三层（扫描 / schema / 种子） |

## 2. 分工

| 模块 | 位置 | 职责 |
|---|---|---|
| 采集核（内核） | `core/driver/src` | 解析锚点、逐帧读玩家/骨骼/物品/投掷物、组帧、发布到 section |
| 通道 | `cs2_shm.c` | 建 section、映射、seqlock 发布、卸载销毁 |
| 契约 | `shared/cs2core_abi.h` | 唯一帧布局定义（v5 + v6 + v7） |
| 显示端 | `cs2ext_port/CS2_External-master` | 映射 section → 解析 → ImGui 渲染（外部透明窗口） |
| 构建 | `tools/build-driver.ps1`、`tools/build-cs2ext.ps1` | cl/link 直编（本机 MSBuild 被策略拦） |
| 验证 | `--frame-check`、`tools/synth-frame.py` | 离线解析与几何校验，不依赖游戏 |

## 3. 数据流

```
cs2.exe ──(PsLookupProcessByProcessId + MmCopyVirtualMemory，无句柄暴露)
   │
   ▼
cs2core.sys  (手工映射；无 DriverObject / 无 DeviceObject / 无服务)
   │  120 Hz 采样 → 组帧 → seqlock 发布
   ▼
\BaseNamedObjects\{GUID 形态的名字}   ← 共享内存 section（驱动持有映射）
   │  OpenFileMapping(FILE_MAP_READ) + MapViewOfFile
   ▼
CS2_External.exe
   │  FrameShm::Read（seqlock 快照）→ FrameData（校验 + 解析）
   ▼
CEntity / CView → Render（方框/骨骼/血条/护甲/装备/弹药/C4/物品/投掷物/雷达）
```

关键点：**驱动与显示端之间没有任何 IPC 调用**。没有 IOCTL、没有管道、
没有窗口消息、没有文件句柄传递。显示端只是把一块只读内存映射进自己的地址空间。

### 3.1 为什么不是"把 client.dll 整块镜像下来"

实体链是四级指针：`client.dll → GameEntitySystem → chunk → entity → scene node`。
每一级都必须先读到上一级的指针，才能算出下一级的地址；同一帧里把
`client.dll` 整块复制过来，显示端仍然要重新解引用一遍，而且镜像体积
100 MB 级、每帧传输不可行。

所以 "dump 到共享缓冲区" 落在**语义层**：驱动在内核里完成指针解引用和字段
采样，把 240 B/玩家 的定长记录写进 section。显示端拿到的是可直接渲染的数据，
全程不需要访问游戏内存。这也是"不读取目标进程"能成立的前提。

## 4. 帧契约

| 区间 | 内容 | 校验 |
|---|---|---|
| `[0, 10280)` | 头 168 B + 32 × 316 B 玩家 | `magic 'C2SE'` + `FNV-1a(players)` |
| `[10280, 12604)` | `AABB[32]` + `item[64]` | `magic 'TAIL'` + `FNV-1a([10280,12600))` |
| `[12604, 13968)` | `gren[24]`（投掷物 + 燃烧区） | `magic 'GRND'` + `FNV-1a([12604,13964))` |

seqlock：`seq` 在 offset 8。写端置奇数 → 写正文 → 置偶数；读端看到奇数或
前后不一致就丢弃这次快照。section 固定 13968 B，诊断帧只写前 10280 B，
尾部显式清零，避免上一次真帧的物品/投掷物残影。

## 5. 通道实现要点

### 5.1 名字

GUID 形态、由目标 pid 派生，两边各算一次，不需要配置文件：

```
a = (0x4C325343 ^ pid) ^ (SALT << 24)
b = (0x9E3779B9 * (pid + 1)) >> 16
c = ((pid << 16) ^ 0x5F3A) & 0xFFFF
d = ((pid >> 3) ^ 0xA1B2C3D4) & 0xFFFF
e = 0x7F4A7C15 + pid
name = Global\{a:08X-b:04X-c:04X-d:04X-e:08X}{pid:04X}
```

`SALT` 是通道代次（当前 2）。显示端先试 2 再试 1，便于"机器上还留着旧实例"
时仍能读到新实例的 section。pid 0 用于"游戏还没开"的诊断帧，这样通道在
没有目标进程时也能被验证。

### 5.2 生命周期

- 第一次发布时创建（`ZwCreateSection` + `ZwMapViewOfSection` 到 System 进程）
- 目标 pid 变化 → 关闭旧 section、按新 pid 重建
- `DriverUnload` → `ZwUnmapViewOfSection` + `ZwClose`，名字随之消失
- 同名残留（上一次崩溃）→ 打开后 `ZwMakeTemporaryObject` 再关句柄，然后重试

### 5.3 为什么不是设备 + IOCTL / 文件 / 管道

| 通道 | 对手能看到什么 |
|---|---|
| DeviceObject | `\Device` 一次枚举就能列出；有 IRP 分发表 |
| 符号链接 | `\GLOBAL??` 可见，且必须注册服务 |
| 命名管道 | `\Device\NamedPipe` 可见，有连接状态 |
| 文件 | 固定路径 + 固定大小 + 固定节拍，minifilter/磁盘扫描可命中 |
| **section** | 只有对象目录里一个 GUID 名，无分发表、无连接、无磁盘痕迹 |

section 不是"隐身"，它是**攻击面最小的一档**：没有可调用的入口点，
只有一块内存。

## 6. 显示端框架

用 `CS2_External`（hzqst 版）作为基础：D3D11 + ImGui、独立透明窗口、
`WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_TOOLWINDOW`，跟随游戏窗口。

为什么不用 Game Bar 组件（UWP）：

| 维度 | UWP 组件 | 外部 Win32 覆盖层 |
|---|---|---|
| 输入注入 | AppContainer 禁止 `SendInput` | 可用（本方案不需要） |
| 部署 | 需要签名清单 + `Add-AppxPackage` 注册 | 一个 exe |
| 更新 | 依赖 WidgetKit 版本 | 重编即换 |
| 崩溃影响 | 组件宿主重启，覆盖层消失 | 独立进程，重开即可 |
| 数据源 | 需要 relay 进程搬帧 | 直接映射 section |

数据源切换只改一层：`FrameShm::Read` → `FrameData::Reload`，其余
（`CEntity` / `CView` / `Render` / `Radar`）不动。

渲染项：方框（普通/四角/填充）、骨骼、血条、护甲条、名字、距离、
武器 + 弹匣、装备字母（H/K/Z/R/D）、C4 携带标记、地面物品、
投掷物 + 半径圈 + 出手点轨迹、雷达、Snapline、帧状态行。

## 7. 实现约束

- 采集端只读：`PsLookupProcessByProcessId` + `MmCopyVirtualMemory`，不创建指向目标进程的句柄
- 不注入、不挂钩、不注册系统回调、不修改目标进程内存
- 不创建驱动对象/设备对象/服务，不写注册表，不落盘日志
- 采样跑在系统工作队列（`ExQueueWorkItem`），不自建线程
- 池标签按加载随机选取，卸载时擦除缓冲与字符串表
- 帧通道只暴露一个 GUID 形态的 section，驱动卸载即消失
- 采样 60 Hz，间隔带抖动；找不到目标时指数退避

## 11. 验证（本机实测）

```
SOURCE shm pid=0
FRAME ok seq=2 flags=0xDEAD0001 screen=0x0 local=0 players=0
TAIL items=none(0) gren=none(0)
```

`flags=0xDEAD0001` = 诊断帧（阶段 1：没找到 cs2.exe），说明
section 创建、seqlock、显示端映射、头部校验全部走通。

合成帧（`tools/synth-frame.py`，5 玩家 + 3 物品 + 2 投掷物）经
`--frame-check <file>` 解析，字段与屏幕框几何全部正确。
